What Ugreen NAS Admin Pro can do

Pro is a separate app for diagnosis and technician work on a UGREEN NAS. The free app stays the everyday tool. Pro is for supporters after a donation, and for selected testers.

Everything below is in the Pro app after a license is imported. Lab and App development are visible only on a tester license.

Problems & errors

One scan of the NAS, the UGOS App Center, and the Pro app on the PC. The scan reports real issues only: no UGOS or Docker noise, SMART only on FAIL or critical counters, and script logs only when they are recent. During boot, “services not started” can appear briefly; a second scan a few minutes later clears that.

  • Scan history marks what is new, resolved, or unchanged since the last scan.
  • Compare any two saved scans (older against newer).
  • Export a support report, or save the current view.
  • The UGOS API port (usually 9443) is set in Settings. If API results stay empty, that port is the first place to check.

Logs

Load log sources from the active NAS by category, then refresh:

  • All
  • Transfers
  • Docker
  • System
  • Scripts / cron
  • Installations / apps
  • Problems & errors

Live tail

Follow a log on the NAS in real time (tail -f). Start, stop, clear, and save. Built-in sources:

  • backup_log.txt
  • UGOS log_serv.slog, docker_serv.slog, storage_serv.slog, entry_serv.slog
  • auth.log
  • syslog / messages

.slog list reads the UGOS service logs on the NAS and adds them as extra tail sources.

Console

An interactive SSH shell to the active NAS profile, without an external terminal. Connect, disconnect, clear the view, and send Ctrl+C. Commands are typed in the app; output stays in the same window. For a sudo password prompt, the NAS password is sent from the command line.

Dumps & support package

Run one diagnostic preset, or build an incident bundle: a ZIP for a forum post or a support thread. The bundle can include a fresh problem scan, an HTML support report, scan history, the Pro session, and the standard dumps. Host, IP, and user can be anonymized.

Presets:

  • Storage & RAID — df, lsblk, mdstat, fstab, short SMART overview
  • Temperatures & fans — sensors, thermal, it86/hwmon, disk temperatures
  • Docker — info, containers, logs, networks, compose paths, docker_serv.slog
  • Network — interfaces, routing, DNS, ports, gateway, networking.log
  • SMB/NFS shares — testparm, smb.conf, exports
  • UGOS & App Center — OS, packages, package logs, log_serv
  • UGOS service logs — tail of /var/ugreen/log/*.slog
  • UGOS services — systemd *_serv, failed units, service status
  • Scripts & cron — /volume1/scripts, papa_jobs, backup_log, *.log
  • Login & SSH — auth.log, ssh journal, last/lastlog, login lines from ctl/log_serv
  • System support — support snapshot: syslog, journal, core UGOS logs
  • Full (support) — every preset above, with size limits
  • Full (tester, unfiltered) — tester license only: every preset without size limits, including full logs, journal, and SMART

Logs and dumps always use the active NAS. The download folder is shared by all profiles.

Storage

Find pools and volumes through the UGOS API, then back them up, restore them, or erase selected user data. The UGOS system stays. System disks are not touched. SSH admin rights and API port 9443 are required.

  1. Analyze detects every pool and volume.
  2. Select a whole pool or individual volumes. Home (/home, including Photos) can be included for backup and restore only.
  3. Backup now streams user data to a .tar.gz in the download folder. @… system folders and the recycle bin are left out. Hard links are stored as normal files. The job is finished only after the local archive passes a restore check. A warning is kept when a single file cannot be read. Size, speed, and ETA are shown; the transfer can be cancelled.
  4. Restore after a disk swap goes to exactly one selected volume, or to Home. Incomplete archives, .., absolute paths, and device or FIFO entries are rejected.
  5. A pre-wipe checklist runs before erase: SSH/API, system disks, RAID and Docker hints, plus two manual confirmations.
  6. Delete selected asks more than once. Verification afterwards checks that the target is gone, RAID is stopped where expected, and the system disk is unchanged.

NAS overview

Compare every saved profile in one list: SSH, the last scan, and live hints (volume at or above 90%, RAID). The most critical NAS sorts to the top. Double-click or Set as active switches the profile and can open Problems for that NAS. With two or more profiles, the sidebar shows a short status.

Test connection in the sidebar checks the active profile.

Watcher

A scheduled health check. It alerts on new scan problems, an SSH outage, or volume/RAID hints.

  • Turn the automatic check on or off.
  • Interval: 1, 6, 12, 24, 48, or 168 hours.
  • One profile, or all NAS profiles.
  • Optional popup when there is something to report.
  • Check now runs it immediately. The last run shows the time and whether it was clean.

Technician

Power-user tools. Each sub-tab keeps the full output.

API

Call the undocumented UGOS REST API. Read-only use is the safe default. Docker and apps are better handled from the console. Presets:

  • Storage — disk list, pool list, volume list
  • Network — interfaces (two variants)
  • System — machine info, CPU/RAM/network, temperature/fans
  • Desktop — SystemStatus, DeviceMonitoring
  • Users — list, groups
  • Hardware — UPS live data, UPS USB info
  • Camera — devices, cameras
  • Docker — container list, and POST to start, stop, or restart a container

Method (GET or POST), path, and a JSON body can be edited. The response is shown in full.

Benchmark

Load the volumes, then run a short dd test (32–512 MiB). The temporary file is deleted afterwards.

Config

A fingerprint of cron, sysconfig, compose files, and service status. Save a snapshot and compare it with the last one later.

Quarantine

Isolate a service (stop and disable): core services, UGOS *_serv, failed units, and app packages. Protected and left alone: ssh, nginx, gateway, storage. Restore one entry, or restore all.

Recovery

Emergency diagnosis over SSH and the UGOS API. Actions are offered only when a check actually fails. Scenarios:

  • Full emergency overview — SSH, UGOS API, web ports, core services, RAID, disk usage, Docker, failed units
  • UGOS web/app unreachable — ports 443/9443, nginx/gateway/filemgr, API login
  • SSH connection — reachability, ssh.service, port 22
  • RAID / storage degraded — mdadm, storage_serv, volume mounts
  • Volume almost full — usage under /volume* (warning at 90%, critical at 95%)
  • Docker will not start — docker.service, docker_serv, docker info

The two repair actions, each with sudo and only after a real finding: restart Docker (docker.service and docker_serv), or restart UGOS web services (nginx and the central UGOS services, unmask/enable/restart, no port kill).

Wake-on-LAN

Read the NAS MAC over SSH, then send a magic packet. Optionally wait until SSH (the port from Settings) answers. WoL has to be enabled in the BIOS or UGOS and on the switch.

Settings, connection, and updates

  • Several NAS profiles, switched from a dropdown. One shared download folder.
  • Import from main app copies connection data from Ugreen NAS Admin.
  • UGOS API port and HTTPS. UGREEN default is 9443. Storage, Technician, Lab, and the dashboard use this port.
  • SSH remembers the first host key and stops if the key changes. UGOS HTTPS remembers the certificate after the fingerprint is confirmed. Both can be forgotten in Settings.
  • The NAS password and the Telegram token for developer reports stay in the Windows vault when it is available. The settings file does not keep those secrets.
  • Check for updates looks only at the Pro GitHub release channel. The download is checked for size and redirects. The installer starts only after signed release metadata. A valid license is required.
  • The license file is pro_entitlement.json, bound to this PC’s fingerprint. A new PC needs a new request.

Testers only

A supporter license does not show these two areas.

App development

Sits above Problems. Three tabs:

  • Apps to test — catalog from the private GitHub repo (the same source as Pro updates). Download a test app and install the UPK yourself in the UGOS App Center. Open the download folder. A badge appears when a new test app is published.
  • Report — pick the app, write what happened, attach screenshots. The report goes to the developer by email or Telegram.
  • Suggestions — the same path, for ideas rather than a bug in one app.

Lab

Tester tools, each with full output that can be copied into a report.

  • Diagnose — a quick check (problem scan plus a short SSH block), or a preset: disk (df -hT), RAID/mdstat, memory, uptime and load, dmesg, Docker process list, UGOS log_serv tail, network, auth.log. A custom SSH command is there only when the developer has specified it.
  • Debug — app version, PC fingerprint, license ok/tier, UGOS API port, active profile, SSH state, last SSH error, and the recent session events.
  • API sweep — probes the known UGOS endpoints, keeps a history, and diffs two sweeps (added, removed, status-code changes).
  • Dashboard — the same UGOS API data the web UI uses (sysinfo, task manager, SystemStatus), to see why the main app’s dashboard might be empty.
  • Camera / RTSP — camera and device lists from the UGOS API, then ping and ffprobe of an IP or rtsp:// URL from the NAS. RTSP passwords with special characters are normalized.
  • SMB / Win32 — explains Windows error 1219 (an SMB credential clash on the PC, not on the NAS) and shows net use.
  • Slog grep — regex search across /var/ugreen/log/*.slog over SSH, with a line cap.
  • Checklists — guided scenarios from the runbook: app cannot connect / SSH failed, storage full / RAID / volume, Docker container will not start, camera / RTSP, NAS slow / high load, backup or transfer stuck. Output can be copied into the report. Support codes in the runbook cover installed UGOS packages and a SMART quick check.
  • Snapshot — save diagnose, API sweep, and dashboard together, then compare with an older snapshot (for example after a firmware update).
  • Runbook — extra commands, checklists, and support codes. A built-in default ships with the app; a JSON file or a URL can replace it.
  • To the developer — bundle notes and files (dumps, ZIP, text), optionally the current problem scan, optionally anonymized. Email goes to ugna@posteo.de. Telegram opens the developer chat, or sends directly when the bot is configured. Full report packs the lab output into one package.
